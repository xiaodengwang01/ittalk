这里保存可跨电脑阅读的学习成果：原理笔记、图解、自测、小型实验和项目说明。用当前 Codex 在本机阅读、讨论和写文件，再将 `docs` 同步到 GitHub。

从 [学习路线](学习路线.md) 选择一个主题，从 [学习进度](学习进度.md) 接续上次内容；[学习协作约定](AGENTS.md) 说明后续如何整理和验证成果。

## 一次学习怎么进行

建议每次 30—60 分钟，只完成一个能说清楚的问题。

1. **确定问题**：例如“16 个元素怎样分给线程”“ACT 为什么输出动作块”。先读少量课程材料，带着问题来讨论。
2. **理解与预测**：让 GPT 用图解或小例子讲解，自己先画一次、算一次或预测一次结果。
3. **检查理解**：回答两三道问题，让 GPT 指出具体错误，再用自己的话重述。
4. **保存成果**：整理为一篇短笔记；记录尚未解决的问题和下一步。需要实验时，附最小代码、实际结果及运行方法。
5. **同步查看**：本机按已有授权使用上传脚本同步，或双击原来的“一键上传.command”。另一台电脑打开 [GitHub 学习目录](https://github.com/xiaodengwang01/ittalk/tree/main/docs) 即可阅读。

这里的建议是先沿用已能访问本机文件的 Codex，不必为学习笔记另外开发 API 工具。应用支持围绕选定文件夹使用文件和上下文；持续协作偏好放在 `AGENTS.md`，学习状态放在进度页。[应用说明](https://learn.chatgpt.com/docs/app) · [项目指导说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 每个主题产出什么

| 成果 | 保存内容 | 何时算完成 |
|---|---|---|
| 原理笔记 | 核心问题、解释、图解或手算、易错点、原始来源 | 能脱离笔记解释关键步骤 |
| 自测记录 | 自己的回答、纠正过程、仍不懂的问题 | 能答对一道变化后的题 |
| 小实验 | 一个最小脚本、运行方法、正确性检查和结果 | 在注明的环境中实际运行并能解释结果 |
| 小项目 | 明确问题、最小功能、样例、验证和使用说明 | 另一人按说明能复现 |

笔记优先 Markdown；图优先 Mermaid 或随文保存的 SVG/PNG；学习脚本可用 Python。少量实验结果写在 Markdown 表格或 JSON 中。现有上传规则会排除 CSV/XLSX 等文件，产出时先检查，不默认为它们已上传。

新文件按主题逐步增加，例如 `gpu/01-线程与索引.md`、`embodied/01-观察到动作.md`。这些是未来命名示例，开始对应主题时再创建。图片和小脚本与对应主题放在一起，不复制多套相同内容。

## 另一台电脑怎么查看

**只看内容**：直接打开 [GitHub 学习目录](https://github.com/xiaodengwang01/ittalk/tree/main/docs)，不需要安装 Python 或同步工具。有访问限制的仓库使用有权限的账号登录。

**下载到本机阅读或交给 GPT 继续处理**：在希望存放学习资料的位置运行一次：

```sh
git clone --depth 1 https://github.com/xiaodengwang01/ittalk.git ittalk-learning
```

后续更新，在本地没有未处理改动时运行：

```sh
git -C ittalk-learning pull --ff-only
```

在那台电脑的 Codex 中打开 `ittalk-learning/docs`，或明确让它读取上述文件。仓库同步的是文件；新聊天应从这些记录恢复学习状态。

当前建议一台电脑负责编辑上传，另一台主要阅读。原工作机的上传脚本在 `docs` 之外，只保存在原机。如果以后改为两台都编辑，再按新机器的系统配置上传入口；遇到双方都有改动时先核对，避免覆盖。
