# 具身智能与 GPU 学习路线

目标是形成能解释、能核对、能逐步复现的成果。具身智能回答“观察如何变成动作”；GPU 原理回答“计算如何分配、数据怎样搬运、耗时从哪里来”。两条路线按主题分别记录，不把两套周计划硬并成一套日历。

下面保留用户提供的六周 GPU 安排和八周具身路线，并将每阶段转换为明确产出。每次只推进一个小问题，按自测与实际验证判断完成情况。

### 第一轮只保留三个小实验

| 实验 | 先写下的预测 | 正确性验收 | 性能验证安排 |
|---|---|---|---|
| 向量加法 | 哪个线程处理哪个元素；多出的线程怎么办 | 与参考结果一致，覆盖不能整除的长度 | 首先验证索引；有兼容 GPU 后再运行课程内核 |
| 改分块大小 | 分块变大时，复用和资源占用分别怎样变化 | 不同分块得到一致结果，包含边界输入 | 在同一兼容 GPU、同一输入条件下对比；不预设越大越快 |
| 融合前后比较 | 哪些中间读写或内核启动可能减少 | 在说明容差的前提下与参考实现比较 | 确认实际执行的内核与融合情况，再测耗时 |

没有兼容 GPU 时，可先用 CPU 小例子验证索引和数值，用手算统计理想化的数据访问。它们属于教学模拟，不能用 CPU 循环耗时推断 CUDA 分块或 Triton 融合的加速比。

真实性能记录至少包含设备、软件版本、输入形状、数据类型、预热、同步、重复次数与统计方式。实验没有实际运行时，保留“待运行”，不填写预计耗时作为结果。

## Mac 上怎样推进

原始工作机于 2026-10-30 检查为 Apple M4、16 GB 内存。第一阶段优先阅读、画图、手算和小型 CPU 验证。PyTorch 提供基于 Metal 的 MPS 后端；是否能在当前安装中使用，需要检查 `torch.backends.mps.is_available()`。[PyTorch MPS 官方说明](https://docs.pytorch.org/docs/stable/notes/mps.html)

GPU MODE 的 CUDA 课程性能实验需要对应的 NVIDIA GPU 环境；Triton 主项目当前列出的支持平台为 Linux，支持硬件列表没有 Apple GPU。因此，按课程路线做真实 GPU 实验时，另行准备符合要求的环境；Mac 本地学习不以先装齐这些依赖为前提。[Triton 支持范围](https://github.com/triton-lang/triton#compatibility)

如果以后希望专门学习 Apple GPU 编程，可再选 GPU MODE 第 31 讲 Metal。它属于另一条实现路径，不必加入当前第一轮任务。[课程目录](https://github.com/gpu-mode/lectures/blob/main/README.md)

## 具身智能八阶段

以下沿用用户提供的《具身智能学习与个人项目路线》。这里保留学习目标和产出，不预填公司的能力比较或实验结论；精读时再核对对应论文、官方实现和版本。

| 阶段 | 要回答的问题 | 最小产出 |
|---|---|---|
| 1 基本语言 | observation、action、state、episode、policy 如何组成闭环？ | 观察到动作的闭环图，注明动作向量的语义依赖机器人和控制方式 |
| 2 机器人数据 | 一条轨迹如何组织？图像、状态和动作怎样对应？ | 小样本字段说明和时间关系图，列出单位与未知项 |
| 3 模仿学习与 ACT | 为什么一次预测一段动作？预测和执行窗口有什么区别？ | 带张量形状的数据流笔记和序列窗口手算 |
| 4 Diffusion Policy | 多种合理动作为什么不能简单取平均？ | 两条可行绕障轨迹及平均轨迹的对照；与 ACT 比较 |
| 5 VLA 与代码阅读 | 图像、语言和机器人状态如何进入策略？ | 只跟一个实现的输入、变换、归一化、输出路径，记录代码版本 |
| 6 前沿路线 | 各家公开了什么证据，哪些仍未知？ | PI、Generalist、DYNA、Sunday 的来源对照，区分官方描述与个人推断 |
| 7 小工具 | 如何可靠检查少量示教数据？ | 一个有样例、验证和使用说明的数据体检器最小版本 |
| 8 公开贡献 | 能解决哪一个经过核对的真实小问题？ | 范围明确的改进材料和学习复盘；对外提交另按用户指令执行 |

开始时使用 [Hugging Face Robotics Course](https://huggingface.co/learn/robotics-course/unit0/1) 和 [LeRobot 模仿学习流程](https://huggingface.co/docs/lerobot/il_robots)。后续按主题选择用户路线中的入口：[数据格式](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)、[ACT](https://tonyzhaozh.github.io/aloha/)、[Diffusion Policy](https://diffusion-policy.cs.columbia.edu/)、[SmolVLA](https://huggingface.co/docs/lerobot/smolvla)、[openpi](https://github.com/Physical-Intelligence/openpi)。无需同时安装这些项目。

### 个人项目的起步范围

优先保留用户路线中的“机器人示教数据体检器”作为候选：限定一种数据格式，先做字段与形状、NaN/Inf、episode 内时间顺序三类检查。使用正常样本和人为构造的异常样本验证，再决定是否扩展；输入来源、单位、规则和告警位置应能查到。

GPU 三个小实验和这个具身项目分开计数。学习到相关阶段再创建项目，不提前生成未经验证的完整实现。

两条路线的连接点是推理延迟与控制循环：理解动作块和执行窗口后，再讨论较快的推理怎样影响重新观察与响应。教学示例只说明机制，真实机器人的效果需要对应系统中的实验。
